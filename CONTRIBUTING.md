# Contributing

Thanks for your interest. Bug reports, new scenarios and adapter fixes are especially welcome.

## Development setup

You need Python 3.12 with [uv](https://docs.astral.sh/uv/), Node.js 20 or newer for the widget checks, and Docker
for the compose stack.

```bash
uv sync
uv run booking-truth --help
npm ci
```

## Checks

Everything CI runs can be run locally:

```bash
uv run ruff check src tests scripts
uv run ruff format --check src tests scripts
uv run mypy
uv run pytest
npm run check
uv run python scripts/check_widget_size.py
uv run python scripts/update_readme_tables.py results/2026-09-27-bench --check
```

The default test run makes no network calls to paid APIs: the agent uses its scripted offline policy
(`FakeLLM`) and the harness uses scripted personas and the lexicon extractor. Tests that talk to a real service are
marked `live` and skip without credentials; the browser test is marked `e2e`:

```bash
uv run playwright install chromium
uv run pytest -m e2e
```

## Scenarios

Scenarios live in `scenarios/` and are documented in `scenarios/README.md`. Run `booking-truth scenarios lint`
before sending one: it validates the YAML and checks that each persona's hidden window overlaps the seeded host
availability. Do not tune a scenario to make a particular agent pass; a scenario should describe a situation a real
prospect creates.

## Datasets

`datasets/tz_phrases.jsonl` and `datasets/belief_extraction.jsonl` are split into dev and held-out test items. The
test-split hashes in `datasets/HASHES.json` were recorded before any tuning. Tune on dev items only, and report on
test items only.

## Pull requests

- Keep changes small and focused, with tests.
- Use conventional commit messages (`feat:`, `fix:`, `docs:`, `test:`, `chore:`).
- If a change affects the benchmark (scenarios, agent prompts or agent code), say so: the published numbers in
  `results/` belong to a frozen version and are only regenerated by a full rerun.
